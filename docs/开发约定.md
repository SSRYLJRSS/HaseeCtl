# HaseeCtl 开发约定

本文件记录本项目的**硬约束**与**踩过的坑**。动代码之前先读一遍，能省掉大半返工。

- 机型基线：神舟战神 Z8D6（认证型号 CV15S，蓝天 Clevo 方案，Insyde BIOS 1.07.07THZX）
- 技术栈：.NET 10 + WPF + Wpf.Ui 4.3.0
- 仓库：<https://github.com/SSRYLJRSS/HaseeCtl>

---

## 1. 架构分层

| 项目 | 职责 | 改动原则 |
| --- | --- | --- |
| `src/HaseeCtl.Core` | 硬件抽象、EC 读写、曲线计算、配置存取、下发引擎 | **最稳定的一层。改这里必须有测试覆盖。** |
| `src/HaseeCtl.Agent` | 托盘常驻、全局热键、开机/唤醒恢复、30 秒自检 | 只做调度，不写硬件逻辑 |
| `src/HaseeCtl.App` | WPF 界面（7 个页面） | 纯 UI，所有操作都经由 `Engine` 下发 |
| `tools/HaseeCtl.Probe` | 只读硬件探针（诊断用） | 只读；写操作必须显式 `--write` |
| `tests/HaseeCtl.Tests` | 33 条单元测试 | 见第 5 节 |

**核心约束：UI 层不得直接碰 EC。** 所有硬件动作走 `Core/Apply/Engine.cs`，这样 Agent、App、热键三条路径的下发逻辑保持一致。

## 2. 硬件依赖（绝对不要删）

这三样属于**官方驱动包**，HaseeCtl 靠它们和 EC 通信：

| 组件 | 位置 | 作用 | 删了会怎样 |
| --- | --- | --- | --- |
| `AcpiBridge.sys` | `C:\Windows\System32\drivers\` | EC 通信驱动（服务 Manual/Running） | 全部功能失效，风扇失控 |
| `HKKbdFltr.sys` | `C:\Windows\System32\drivers\` | 键盘过滤驱动 | Fn 热键完全不可用 |
| `InsydeAirplanemodehid.dll` | `native/`，安装后随程序分发 | 飞行模式切换 | 飞行模式按钮无效 |

设备节点：`ACPI\CLV0001\1`（Acpi Bridge）。状态必须是 OK。

**可以禁用的**：`CCDCHUService`、`HKClipSvc`（官方 CC 的两个自启服务，本机已置为 Stopped + Disabled，用 `_verify/官方CC_禁用自启.ps1 -Action Restore` 可回退）。

## 3. 编码约定（血泪教训）

### 3.1 PowerShell 脚本必须带 UTF-8 BOM

PowerShell 5.1 在无 BOM 时按 GBK 解码，中文注释和字符串会直接炸成语法错误（报错信息还误导人，说"意外的标记 }"）。所有 `.ps1` 一律存为 **UTF-8 with BOM**。

改文件头时**必须整文件重读重写并统一 `encoding='utf-8-sig'`**。只做局部字符串替换会把 BOM 写到错误位置，文件头变成 `?Add-Type`，报 `无法将"?Add-Type"项识别为 cmdlet`。

### 3.2 内联 C# 用 `System.Drawing` 必须显式引用

```powershell
Add-Type -ReferencedAssemblies 'System.Drawing' @"
    ... new System.Drawing.Bitmap(...) ...
"@
```

只写 `Add-Type -AssemblyName System.Drawing` **不够**——PowerShell 5.1 的 CodeDom 编译器默认不引用它，会报 `未能找到类型或命名空间名称"Bitmap"`。

### 3.3 窗口截图用 `PrintWindow`，不要靠"把窗口移到后台"

```csharp
PrintWindow(hWnd, hdc, 2 /* PW_RENDERFULLCONTENT */);
```

`ShowWindow(SW_MINIMIZE)`、`MoveWindow(20000,20000)`、`SetWindowLong(GWL_EXSTYLE, WS_EX_TOPMOST)` 对常驻进程的窗口**全部无效**（对方会自己抢回置顶）。`PrintWindow` 直接抓窗口自身位图，不经过屏幕合成，绕开一切遮挡。

### 3.4 长脚本先落盘再执行

超过一两百行、或含引号/反斜杠/非 ASCII 的脚本，先写成 `.py` / `.ps1` 文件再跑。内联执行时的转义问题排查成本远高于写文件。

### 3.5 Python 处理 CRLF 文件要按 `\r\n` 匹配

项目里部分文件是 CRLF 行尾（`FanPage.xaml.cs` 就是）。用 `\n` 匹配会失败或破坏文件。

## 5. 测试

`dotnet test` 在本机**不可用**（`testhost.x86` 报 `Win32Exception (5): 拒绝访问`，各种 `-p:Platform` / `dotnet vstest` 绕法都失败）。改用自研反射运行器：

```bash
export TMP="F:\vibecode\REA_CON\_verify\_tmp_testdir"
export TEMP="$TMP"          # 不设会被沙箱拒绝 Directory.CreateDirectory
cd /f/vibecode/REA_CON/_verify/TestRunner
dotnet build -c Release     # ← 改版本号后必须重建，见下
./bin/Release/net10.0-windows10.0.19041.0/TestRunner.exe \
  'F:\vibecode\REA_CON\HaseeCtl\tests\HaseeCtl.Tests\bin\Release\net10.0-windows10.0.19041.0\HaseeCtl.Tests.dll' \
  | iconv -f GBK -t UTF-8
```

**验收线：`PASS=33 FAIL=0 SKIP=0`。**

两个必踩的坑：

1. **必须显式传程序集完整路径**。`TestRunner/Program.cs:7-14` 无参时用 `Directory.GetCurrentDirectory()` 拼路径，会把 `HaseeCtl\tests\...` 拼成缺一级的错路径，然后输出 GBK 乱码"找不到测试程序"。
2. **改了 `<Version>` 就必须先重建 TestRunner**。否则报 `Could not load file or assembly 'HaseeCtl.Core, Version=1.0.1.0'`。

## 6. 界面约定

### 6.1 配色

全局暗色（WPF-UI `ThemesDictionary Theme="Dark"`），**强调色统一成灰阶**，禁止出现系统蓝：

`App.xaml.cs` 启动时调 `ApplicationAccentColorManager.Apply()` 把四档强调色压成 `#5A5A5A / #E6E6E6 / #FFFFFF / #D0D0D0`。系统档必须是中灰而不是白——它是**文字选中背景**，纯白会导致选中文字看不清。

新增控件如果出现蓝色，多半是该控件吃系统强调色；参考 `App.xaml` 里现成的 `Segment` / `Card` / `CardTitle` / `Hint` / `Metric` / `FieldLabel` 样式复用，不要自己造。

### 6.2 按钮原则

界面改版后**每个卡片最多留 2–3 个按钮**。风扇页从 12 个减到 8 个的原则是：

- 「选中即生效」——下拉换方案立刻下发，不需要"应用"按钮
- 「拖完即保存」——曲线松手后 300ms 去抖自动保存 + 下发，不需要"保存"按钮
- 校验失败**在提示行显示红字，不弹窗**

### 6.3 截图

程序自带截图模式，不受窗口遮挡影响：

```powershell
HaseeCtl.App.exe --shot "输出目录"    # 渲染 7 页为 0-dashboard.png … 6-settings.png，1500×1080
```

改完界面要重截并更新 `docs/screens/`，README 直接引用这些图。

## 7. 数据与配置

| 内容 | 路径 |
| --- | --- |
| 配置 | `%APPDATA%\HaseeCtl\settings.json` |
| 日志 | `%LOCALAPPDATA%\HaseeCtl\logs\haseectl-YYYYMMDD.log`（保留 14 天，自动清理） |
| 安装目录 | `%LOCALAPPDATA%\Programs\HaseeCtl` |

配置写入是**原子**的：先写 `settings.json.<PID>.tmp` 再 `File.Move(overwrite: true)`。这样 App 和 Agent 同时保存也不会写坏文件。

`settings.json` 的键名是**小写驼峰**（`fan` / `mode` / `profiles` / `activeProfile` / `cpu` / `gpu1`），不是 .NET 属性名。手改配置时注意。

## 8. 版本管理与发布

```bash
# 1. 改 Directory.Build.props 的 Version
# 2. 构建 + 测试（33 条全绿）
dotnet build -c Release && .\build.ps1
# 3. 提交、打标签、推送
git add -A && git commit -m "..." && git tag vX.Y.Z && git push && git push --tags
# 4. 打包发布
Compress-Archive -Path dist\HaseeCtl\* -DestinationPath dist\HaseeCtl-vX.Y.Z-win-x64.zip
gh release create vX.Y.Z dist\HaseeCtl-vX.Y.Z-win-x64.zip --title "..." --notes-file notes.md
```

**不要用 `git diff` 判断自己的改动。** 仓库工作区历史上出现过大量遗留改动，`git diff` 会把别人的未提交修改算进来。正确做法：改之前先备份到 `_backup_<主题>_<时间戳>/`，改完用 `diff -u _backup_xxx/文件 源文件` 对比。

## 9. 硬件操作安全边界

- **只读优先**。诊断先用 `HaseeCtl.Probe.exe`（无参即只读），确认真实值再动手。
- **不碰固件、不改注册表电源计划、不动 BIOS 设置**。
- **不擅自卸载官方软件或驱动**。要禁用只禁用服务自启，且必须保留 `-Action Restore` 回退路径。
- **写 EC 前想清楚恢复路径**。风扇曲线、充电上限这类设置掉电后仍由 EC 保持。
- 涉及硬件下发的改动，必须真机手测，不能只靠 build 通过。

## 10. 已知限制

- 过温兜底：`FanCurve.cs` 刻意不设软件下限（注释说明 EC 和 BIOS 表已强制硬件要求），不要"顺手补上"。
- Fn + 触控板：加 `SendCtrlF24` 会导致二次切换，当前不处理。
- 飞行模式写 HKLM，需要管理员权限，非管理员运行时该功能会失败（属预期）。
- Agent 自启目前靠启动文件夹快捷方式（`schtasks` 在部分环境创建失败）。
- 睡眠唤醒恢复逻辑存在但尚未在日志中实证过，需要实测。

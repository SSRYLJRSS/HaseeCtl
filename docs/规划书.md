# HaseeCtl 整体规划书

神舟 HASEE CV15S（蓝天 Clevo 方案，Insyde BIOS）Control Center 的轻量替代品。
官方程序卸载后，本程序负责风扇、性能模式、充电上限、显卡切换、键盘灯以及 Fn 热键。

## 1. 目标与验收

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | 风扇自定义曲线，多套配置可保存 | 可新建/重命名/删除配置；重启、睡眠唤醒、切换性能模式后曲线仍生效 |
| R2 | 性能模式（安静/省电/性能/娱乐） | 界面和 Fn 热键都能切换，开机与唤醒后恢复上次模式 |
| R3 | 充电上限（FlexiCharger） | 读出 BIOS 允许的起止值，开关和数值可设置 |
| R4 | 显卡模式（独显直连 / MSHybrid） | 只显示 BIOS 支持的选项，切换前提示需要重启 |
| R5 | 键盘灯 | 开关、4 档亮度、官方 17 种预设色、官方动态效果 |
| R6 | Fn 热键替代 FnKey | Fn+1 风扇全速/自动、性能模式循环、摄像头、触控板、飞行模式、键盘灯亮度，带 OSD |
| R7 | 稳定 | 驱动不可用时不崩溃；单实例；日志可查；开机自启 |
| R8 | 轻量 | 安装后 < 300MB（实际目标 < 30MB），常驻进程内存尽量小 |

## 2. 硬件接口（逆向结果）

所有功能都经过 AcpiBridge 驱动（设备 `ACPI\CLV0001`，接口 GUID `{86994c74-ad43-4812-b7e7-0c420b5c5fd7}`）。
不再依赖官方的 `InsydeDCHU.dll`，直接用 `DeviceIoControl` 重写：

- `0x322400` WMI 方法调用：输入 0x420 字节（方法 GUID `93F224E4-FBDC-4BBF-ADD6-DB71BDC0AFAD`、`_DSM`、命令号、256 字节参数），输出 0x40C 字节（整数或缓冲区）。
- `0x32240C` App 设置区：16 页 × 256 字节，存在驱动侧。官方程序把状态放在这里，本程序读写与官方兼容的字段。
- `0x322404` / `0x322408` 热键事件：等待事件后读取键码。

| 功能 | 命令 |
| --- | --- |
| 风扇实时数据 | WMI 12 |
| 风扇默认表、键盘类型 | WMI 13 |
| 写风扇曲线 | WMI 14（4 点曲线，中间两点可调，含斜率） |
| 风扇模式 | SetWMI(121, 1, mode)：0 自动、1 全速、6 自定义、8 慢速 |
| 风扇偏移 | SetWMI(121, 14, x) |
| 性能模式 | SetWMI(121, 25, mode) + App(1,1)；EnergyStar SetWMI(79, x) |
| BIOS 特性表 | Ex(4, {8}) |
| 充电上限 | 读 Ex(4,{30})，写 Ex(4,{31,status,start,stop}) |
| 显卡模式 | 读 Ex(4,{21})，写 Ex(4,{22,value}) 后重启 |
| 键盘灯 | SetDCHU_Data(103, 32 位命令) |
| 摄像头 | SetWMI(34, 0/1) |
| 飞行模式灯 | SetWMI(19, 1) + SetWMI(121, 26, 0/1) |

## 3. 官方程序"记不住风扇设置"的原因

1. 风扇界面打开时，若注册表 `HKCU\Software\ControlCenter3.0\Fan\First_run` 不存在，会恢复默认曲线并切回自动。本机这个键不存在，所以每次都重置。
2. 每次切换性能模式，FnKey 都把风扇模式写回自动；只有"重启/唤醒后的第一次"才恢复自定义。
3. 曲线只存一份，没有多配置。

本程序的做法：风扇配置存在自己的 `settings.json`；开机、唤醒、切换性能模式、电源插拔之后统一执行"重新应用"（写曲线并设模式 6）；另有定时校验，发现 App(4,5) 被改回去时重新应用。

## 4. 架构

```
HaseeCtl.Core   硬件访问、协议编码、配置存储（无 UI）
HaseeCtl.Agent  常驻托盘进程：热键、OSD、开机/唤醒恢复（NativeAOT，约 1-3MB）
HaseeCtl.App    WPF 主界面（按需打开，关闭即退出）
```

- 运行时：.NET 10。系统已装 .NET 10 桌面运行时；App 用框架依赖发布（几 MB），Agent 用 NativeAOT（不依赖运行时，内存小）。
- UI：WPF + WPF-UI 4.3（Fluent 风格，深浅色跟随系统）。
- 配置：`%APPDATA%\HaseeCtl\settings.json`；日志：`%LOCALAPPDATA%\HaseeCtl\logs`。
- 自启动：任务计划程序"登录时运行"（普通用户权限即可访问驱动，已实测）。
- App 与 Agent 通信：App 修改配置后写 settings.json 并通过命名管道通知 Agent 重新加载，硬件写入统一由 Agent 执行；Agent 未运行时 App 直接调用 Core。

## 5. 热键事件来源

官方服务 `CCDCHUService` 属于驱动包，卸载 Control Center 后仍保留。它独占热键事件并写入事件日志 `OutLog`（`Arg001^键码`）。

- 服务存在且 App(1,12)==1：订阅事件日志 OutLog。
- 否则：自己调用 `0x322404/0x322408` 等待事件。

键码：89 性能模式循环、143 风扇全速、112 风扇自动、246/247 摄像头、93 触控板、133/134 飞行模式、129/130 键盘灯亮度、158/159 键盘灯开关、149 打开主界面。

## 6. 开发阶段

1. Core：驱动访问 + 只读探测命令（`HaseeCtl.Agent --probe`），在本机验证读数与官方一致。
2. Core：风扇/性能/充电/显卡/键盘灯写入接口 + 单元测试（编码与官方字节一致）。
3. Agent：托盘、热键、OSD、恢复逻辑、日志。
4. App：仪表盘、风扇曲线编辑器、性能、电池、显卡、键盘灯、设置页。
5. 安装/卸载脚本（自启动任务）与使用说明。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 写错 EC 参数导致风扇异常 | 曲线输入做范围限制（温度 1–100，占空比单调递增），只发送与官方相同格式的数据；提供"恢复默认" |
| 官方 FnKey 与本程序同时运行 | 检测 FnKey.exe 时在界面提示；定时校验保证最终状态是本程序设置的 |
| 驱动不存在或调用失败 | 所有硬件调用捕获异常，记录日志，界面显示"不可用" |
| 显卡切换需要重启 | 二次确认后才写入并重启 |
